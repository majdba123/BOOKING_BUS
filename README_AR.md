# منصة ERP لإدارة شركات النقل

> منظومة متكاملة ومتعددة الشركات لإدارة عمليات النقل والحجوزات، تشمل الأسطول والسائقين والمسارات والرحلات والحجوزات والتكاليف التشغيلية وخدمات المسافرين عبر تطبيقات الويب والموبايل.

[English README](README.md)

## نظرة عامة

**Transportation ERP Platform** هي منصة متكاملة لإدارة شركات النقل البري بالحافلات، تجمع بين إدارة العمليات الداخلية للشركة وخدمات الحجز الموجهة للمسافرين ضمن منظومة واحدة.

المشروع ليس مجرد تطبيق لحجز تذاكر الحافلات؛ بل يتضمن Backend مبنياً باستخدام Laravel وواجهة ويب باستخدام Vue وتطبيق موبايل باستخدام Flutter، مع مجموعة واسعة من الوظائف المتعلقة بإدارة شركات النقل وتشغيل الرحلات وخدمة المسافرين.

## نطاق المنصة

### إدارة شركات النقل

تغطي المنصة مجموعة من العمليات التشغيلية الأساسية لشركات النقل، من ضمنها:

- إدارة بيانات الشركة وعملياتها التشغيلية
- إدارة الأسطول والحافلات
- إدارة السائقين وربط السائقين بالحافلات
- إدارة المسارات والمحطات والتوقفات
- إنشاء الرحلات وإدارتها ومتابعة حالاتها
- إدارة المقاعد والحجوزات
- إدارة تكاليف الصيانة
- إدارة تكاليف التأمين
- حسابات وتقارير مرتبطة بأرباح الرحلات والعمليات

### الحجز وخدمات المسافرين

تتضمن المنصة وظائف موجهة للمسافرين، منها:

- استعراض الرحلات والبحث عنها
- عرض الرحلات حسب المسار
- استعراض الرحلات والحافلات المتاحة
- اختيار المقاعد وإنشاء الحجوزات
- إلغاء الحجوزات
- إنشاء وإدارة طلبات الرحلات الخاصة
- اختيار العروض المقدمة للرحلات الخاصة
- إدارة الملف الشخصي والعناوين
- إضافة شركات النقل إلى المفضلة
- تقييم الرحلات والسائقين
- متابعة الحجوزات وحالاتها
- إرسال الاستفسارات
- خدمات الإشعارات والتحديثات اللحظية

### إدارة السائقين

توفر المنصة مسارات تشغيلية خاصة بالسائق، من بينها:

- معرفة الحافلة المسندة للسائق
- استعراض الرحلات المعلقة والسابقة
- بدء الرحلة وإنهاؤها
- متابعة نقاط التوقف أثناء الرحلة
- التحقق من حجوزات المسافرين عبر QR
- إدارة الملف الشخصي للسائق
- إرسال الموقع الجغرافي أثناء الرحلة
- استعراض التقييمات وسجل الرحلات

### الإدارة العامة للنظام

توجد واجهات API مخصصة للإدارة تشمل، وفق المسارات المسجلة في الـBackend:

- إدارة المناطق والبيانات الجغرافية
- مراجعة طلبات شحن الرصيد
- إدارة الاستفسارات
- استعراض المستخدمين وتفاصيلهم
- استعراض شركات النقل
- متابعة الحافلات والسائقين والرحلات والحجوزات لكل شركة
- عرض معلومات متعلقة بالأرباح
- لوحة معلومات إدارية

## الأدوار الرئيسية في النظام

يعكس الـBackend مسارات منفصلة لعدة أنواع من المستخدمين:

- **Admin** — إدارة النظام ومراقبة الشركات والمستخدمين والعمليات
- **Transportation Company** — إدارة الشركة والأسطول والسائقين والرحلات والحجوزات والتكاليف
- **Driver** — إدارة الرحلات المسندة ومراحل الرحلة والتحقق من الحجوزات وإرسال الموقع
- **Passenger / User** — البحث والحجز وإدارة الرحلات الخاصة والمفضلة والتقييمات والملف الشخصي

## الوظائف التشغيلية الرئيسية

### الأسطول والحافلات

- إنشاء الحافلات وتحديثها وحذفها
- استعراض الحافلات حسب الحالة
- إدارة المقاعد
- ربط السائق بالحافلة وإلغاء الربط
- متابعة تكاليف الصيانة والتأمين

### المسارات والرحلات

- إنشاء وإدارة المسارات
- إدارة نقاط التوقف
- إنشاء الرحلات وتحديثها وإلغاؤها
- ربط الحافلات بالرحلات
- استبدال الحافلة المرتبطة بالرحلة
- استعراض الرحلات حسب الحالة

### الحجوزات

- استعراض المقاعد المتاحة
- إنشاء الحجز
- إلغاء الحجز
- استعراض الحجوزات حسب الحالة
- عرض حجوزات رحلة أو حافلة محددة

### الرحلات الخاصة

يمكن للمستخدم إنشاء طلب رحلة خاصة، بينما تستطيع شركات النقل تقديم عروض مرتبطة بهذا الطلب، وبعد ذلك يستطيع المستخدم اختيار العرض المناسب وفق التدفقات المسجلة في الـAPI.

### التسعير والتكاليف

يتضمن الـBackend وظائف مسجلة لـ:

- Dynamic Pricing
- حساب المسافات
- تكاليف الصيانة
- تكاليف التأمين
- حسابات مرتبطة بأرباح الرحلات

## المصادقة والتحكم في الوصول

يستخدم الـBackend **Laravel Sanctum** للمصادقة على طلبات الـAPI.

كما توجد مجموعات Routes محمية ومخصصة لأدوار مختلفة، منها:

- Company middleware
- Admin middleware
- Sanctum authentication
- Request throttling للمسارات المحمية الرئيسية

## الوظائف اللحظية

يحتوي المشروع على تكامل مع **Pusher**، بالإضافة إلى event خاص بتحديث الموقع الجغرافي للسائق أثناء الرحلة، ما يدعم تدفقات مرتبطة بالتحديثات اللحظية وتتبع الرحلة.

## هيكل المستودع الحالي

```text
.
├── booking_bus/                 # Laravel Backend
│   └── booking_bus_front/       # Vue Web Application
├── Mobile_App/
│   └── mobile_app/              # Flutter Mobile Application
├── docs/                        # الوثائق التقنية للمشروع
└── README_AR.md                 # النسخة العربية من README
```

تم الإبقاء على أسماء ومسارات مجلدات المصدر الحالية خلال مرحلة التنظيف الحالية لتجنب كسر أي مسارات أو إعدادات أو افتراضات مرتبطة بالبناء والتشغيل. إعادة تسمية المجلدات إلى بنية مثل `backend/` و`web/` و`mobile/` مؤجلة حتى يتم التحقق من التشغيل والبناء بشكل كامل.

## الإعدادات والأمان

تم تجهيز ملفات مثال آمنة للإعدادات الخاصة بالـLaravel والـVue، بحيث لا تكون القيم الحساسة جزءاً من الكود المصدري.

كما أصبح عنوان الـAPI في تطبيق Flutter قابلاً للتغيير باستخدام `--dart-define` مع الحفاظ على عنوان التطوير المحلي السابق كقيمة افتراضية خلال مرحلة التنظيف الحالية.

للمزيد راجع:

- [إدارة الإعدادات والأسرار](docs/configuration.md)

يجب عدم حفظ كلمات المرور أو الـtokens أو المفاتيح السرية الحقيقية داخل المستودع.

## الاختبارات

يحتوي Laravel Backend على اختبارات Feature وUnit موجودة فعلياً داخل المشروع، وتشمل أجزاء مرتبطة بالمصادقة والحجوزات والرحلات وبعض منطق العمل.

كما يحتوي مشروع Vue على إعداد لاختبارات Unit.

تمت إضافة مسار تحقق عبر GitHub Actions لفحص Laravel Backend وVue Web Client، لكن لا يتم اعتبار البناء أو الاختبارات ناجحة إلا بعد تنفيذها والحصول على نتائج فعلية.

## حالة المشروع الحالية

تمت إعادة تقديم المستودع ليعكس طبيعته الحقيقية كمنصة ERP متخصصة في إدارة شركات النقل والحجوزات، بدلاً من ظهوره كمشروع بسيط لحجز الحافلات.

مرحلة التنظيف الحالية تركز على:

- تحسين عرض المشروع على GitHub
- توثيق البنية والوظائف
